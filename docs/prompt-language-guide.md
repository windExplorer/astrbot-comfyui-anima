# 提示词语言规范（真人 / 动漫工作流）

> 适用插件：`astrbot_plugin_comfyui_anima`（AstrBot × ComfyUI 绘图插件）
> 适用读者：插件使用者、接入本插件的大模型（LLM）工具、知识库维护者
> 文档定位：本文规定**不同工作流类型下，提示词（prompt）应使用什么语言**的规范。其余指令用法、参数说明请参见仓库内 `README.md` 与 `/drawhelp` 帮助文本。

---

## 1. 背景：工作流为什么分类型

插件中的每个工作流在配置中都有一个布尔字段 **`is_anima`**（`_conf_schema.json` 内定义）：

| `is_anima` 值 | 含义 | 典型画风 | 中文提示词处理 |
| --- | --- | --- | --- |
| `true` | Anima / 二次元 / 动漫工作流 | 动漫、插画、二次元 | **会被翻译**：提交前若提示词含中文，会调用 Danbooru 标签服务器把中文转成英文 Danbooru 标签 |
| `false`（默认）或缺失 | 真人 / 写实工作流 | 真人照片、写实摄影 | **不翻译**：中文提示词原样进入 ComfyUI，直接使用 |

翻译逻辑位于插件 `main.py` 的绘图主流程（`if wf.get("is_anima") and danbooru is not None and self._has_chinese(positive): ...`）：
- 仅当工作流 `is_anima=true` **且** 提示词包含中文字符时，才发起 Danbooru 翻译；
- 纯英文提示词（无论何种工作流）都直接作为最终 prompt，跳过翻译；
- 真人工作流（`is_anima=false`）即使写了中文也**不会**被翻译。

> 因此，**语言选择不仅是约定，也直接影响最终送到 ComfyUI 的 prompt 内容**。本文的规范正是为了让"人写的话"和"机器最终执行的 prompt"保持一致、可控。

---

## 2. 核心规范

### 2.1 真人 / 写实工作流（`is_anima` 为 `false` 或缺失）

- **可用语言**：中文 **或** 英文。
- **首选语言**：**中文**。
- **例外**：仅当用户**明确要求用英文**（例如"用英文描述""write in English"）时，才使用英文。
- **理由**：真人工作流不接 Danbooru 翻译，中文会原样进入模型 prompt。对大多数中文用户与中文 LLM 而言，直接用中文既自然又可控，避免翻译环节引入不确定性。

```text
✅ 推荐：  /画 真人 一个穿着白裙子的女孩，站在海边，逆光，胶片质感
✅ 用户要求英文时：  /draw --wf realistic1 a girl in white dress on the beach, backlit, film grain
❌ 不建议（无必要）：把中文硬翻成英文再喂给真人工作流
```

### 2.2 动漫 / 二次元工作流（`is_anima` 为 `true`）

- **强制语言**：**英文**。
- **禁止**：用中文作为最终提示词。
- **例外**：无（即便用户用中文描述需求，也应先转换为英文 Danbooru 风格标签再提交）。
- **理由**：
  1. 动漫工作流底层依赖 Danbooru 标签体系，英文化、标签化（如 `1girl, solo, white dress, beach, backlight`）才是该工作流预期的输入形式；
  2. 直接写中文虽会被插件自动翻译，但自动翻译的结果不可控（依赖 Danbooru 服务器可用性与标签覆盖），**主动写英文能获得更稳定、更精确的出图效果**；
  3. 标签化英文（逗号分隔、小写、无自然语言）比完整英文句子更贴合 Anima 类工作流。

```text
✅ 推荐：  /画 动漫 1girl, solo, white dress, beach, backlight, film grain, masterpiece
✅ 用户说中文需求时，先转英文：用户"画个动漫少女在海边" → prompt="1girl, solo, beach, sunny, smile"
❌ 禁止：  /画 动漫 一个穿着白裙子的女孩站在海边   （中文直接当最终 prompt，不走标签体系，效果不可控）
```

## 3. 给大模型（LLM）工具调用的硬性约束

当由 LLM 通过 `comfyui_draw` / `comfyui_img2img` 等工具自动生成 prompt 时，**必须遵守以下规则**：

1. **判断工作流类型**：
   - 通过 `comfyui_workflows` 查询目标工作流的 `is_anima` 字段；
   - 若未指定工作流（留空走默认），按默认工作流的 `is_anima` 判断；默认工作流通常是真人类型，则首选中文。

2. **生成 prompt 的语言**：
   - 目标工作流 `is_anima == true` → prompt **必须为英文标签化描述**，不得输出中文。
   - 目标工作流 `is_anima == false` → prompt **首选中文**；仅当用户明确要求英文时才输出英文。

3. **即使用户用中文提需求**：
   - 动漫工作流：LLM 负责把中文意图**翻译并改写为英文 Danbooru 标签**，而非原样透传中文；
   - 真人工作流：LLM 可直接用中文表达画面描述（无需翻译），除非用户要求英文。

4. **图生图（img2img）同样适用**：
   - `comfyui_img2img` 的 `prompt` 字段同样遵循上述语言规则；
   - 注意图生图不需要描述参考图内容本身，只需描述"变换意图"，并按工作流类型选择语言。

> 示例：用户说"把这张照片变成动漫风格的帅哥"。
> 正确做法：识别为图生图 + 动漫工作流 → `img2img_workflow` 选名称含"动漫/二次元"的，`prompt` 用英文标签：`1boy, handsome, anime style, sharp eyes`。
> 错误做法：把"变成动漫风格的帅哥"这段中文直接塞进动漫工作流的 prompt。

## 4. 速查表

| 场景 | 工作流 `is_anima` | 提示词语言 | 是否经 Danbooru 翻译 |
| --- | --- | --- | --- |
| 真人文生图（默认） | `false` | **中文首选**（用户要求英文则用英文） | 否，中文原样送入 |
| 真人图生图 | `false` | **中文首选** | 否 |
| 动漫文生图 | `true` | **必须英文**（标签化） | 是（若写了中文才翻译；建议直接写英文跳过） |
| 动漫图生图 | `true` | **必须英文**（标签化） | 是 |
| 用户明确要求英文 | 任意 | 英文 | 依 `is_anima` 而定 |

---

## 5. 常见误区

- **误区**：动漫工作流写中文"会被自动翻译所以无所谓"。
  **正解**：自动翻译依赖 Danbooru 服务可用性和标签覆盖，结果不可控；主动写英文标签更稳更准。
- **误区**：真人工作流也该写英文才"专业"。
  **正解**：真人工作流不翻译，中文即最终 prompt，用中文更自然、更可控，无需强行英文。
- **误区**：`is_anima` 字段可以随便填。
  **正解**：它直接决定中文是否被翻译、以及该工作流属于哪类语言规范，配置时必须与真实工作流画风一致。

## 6. 配置约定（管理员）

在 `_conf_schema.json` 的工作流配置中，务必如实填写 `is_anima`：

```json
{
  "name": "realistic_photo",
  "is_anima": false,
  "prompt": "..."
}
```

```json
{
  "name": "anima_illust",
  "is_anima": true,
  "prompt": "..."
}
```

- 动漫类工作流：`is_anima: true` + 启用 `danbooru` 标签服务器，保证中文可翻译、英文直接用；
- 真人/写实类工作流：`is_anima: false`，无需依赖 Danbooru，中文提示词直达模型。
