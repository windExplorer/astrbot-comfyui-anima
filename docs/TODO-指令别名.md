# TODO：「画」系中文绘图指令（新增指令，非 /draw 别名）

## 需求

用中文触发词也能绘图，且「画 + 工作流名」可指定工作流：

- `/draw 提示词` —— 原指令，用默认工作流（保留）
- `/画<工作流名> 提示词` —— 用指定工作流（如 `/画真人 一个女孩`）
- `/画 提示词` / `/绘图 提示词` / `/绘画 提示词` / `/画图 提示词` / `/画画 提示词` —— 用默认工作流

> ⚠️ 实现方式：**新增指令（正则匹配），不是给 `/draw` 加 alias。**
> 之前研究 `@filter.command` 的 `aliases` 参数是走偏了——直接新增正则指令更干净，
> 且与 `/draw` 并存、互不冲突。

## 实现（已完成 ✅，见 main.py）

- 新增 `cmd_draw_wf`，`@filter.regex(r"^[/／]画\S*")` 匹配所有「画」系触发词。
- 类属性 `_DRAW_DEFAULT_TRIGGERS = {"画","绘图","绘画","画图","画画"}`：
  - trigger 命中默认集 → 用默认工作流；
  - 否则 `trigger[1:]` 即工作流名（如 `画真人` → `真人`）。
- 复用 `_parse_draw_args` + `_do_draw`，`--lora/-w/-h/-seed` 等照常可用；`--wf` 优先级最高。
- 找不到指定工作流 → 俏皮提示并退回默认工作流（`_WF_HINTS["not_found"]`）；
  只写触发词没给提示词 → 撒娇提醒（`_WF_HINTS["no_arg"]`）。
- `/drawhelp` 已补充分类说明。

## 设计取舍（已知）

- `/画画` 这类词**优先按默认工作流**处理（不会当成「画 + 名为『画画』的工作流」）。
  即默认触发词优先级最高；若真有名为「画画」的工作流，需用 `/draw --wf 画画` 指定。
- `/画` 后必须紧跟非空白才识别为「工作流名」；`/画 一个女孩`（空格）走默认工作流。
