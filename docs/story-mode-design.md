# 剧情推演模式(隐藏功能)设计文档

> 状态:设计确认(待实现,目标版本 v5.0.12)
> 关联:用户需求「剧情推演场景防死循环 + 剧情模式白名单」
> 说明:本文档仅记录方案,**尚未落地代码**。

---

## 1. 背景与问题

在「剧情推演」场景下,用户会对 LLM 说类似"每几句话发一张图"。LLM 调用 `comfyui_draw` 画图成功后,插件返回一条「本轮已调用,请勿再调用」类的收尾指令。但 LLM 没有正确理解这是**强制停止信号**,约 10 秒后又调用了 `comfyui_draw`,且这次参数为空 `{}`。

此时若插件对空 prompt 做「兜底提取」(从会话历史里捞文本当 prompt),就会把用户之前说的"自己描述场景,自己叫,自己动"这类台词当成画面描述传进去,导致画出错误内容,并陷入「空参 → 兜底 → 再空参」的循环,持续刷图。

## 2. 根本原因

1. **LLM 未把收尾指令当强制停止信号**:收到"本轮已调用,请勿再调用"后仍重试,而不是自然收尾。
2. **工具对空 prompt 兜底提取(旧版)**:`comfyui_draw` 在 prompt 为空时,不是直接报错,而是从对话历史兜底抓取文本当 prompt,造成错误传递与死循环。
3. **缺少"剧情推演模式"的明确控制机制**:普通模式与剧情模式混在一起,没有开关/白名单区分谁能进剧情模式。

## 3. 用户需求

- **普通模式**:正常对话,用户说"画一张"→画完就停,等下一步指令。
- **剧情推演模式(隐藏)**:用户说"进入剧情模式"后,LLM 自动规划剧情步骤、推进场景、发文本配图,每步发图或每几步发一张(首尾必发),推演完或用户说"停"才结束。
- 需要有白名单控制谁能进剧情模式,不在白名单则拒绝。
- 需要明确"收到收尾指令必须停止"的规则,杜绝死循环。

## 4. 现状核对(哪些已经具备)

经核对插件 v5.0.x 源码,用户方案里的**第 2 点(空 prompt 直接报错)与第 3 点(防死循环标记)已经实现**,无需重复开发:

- **空 prompt 直接报错**:`main.py` 的 `comfyui_draw` 入口(line ~5961)已实现——不带 `source`(即 LLM 直接调)且 prompt/prompts 均为空时,**一律直接返回错误、绝不去对话历史兜底提取**,并要求模型把画面描述填进 prompt 后再调一次。其注释正写的是第 1 节描述的那个死循环 bug。
- **单轮出图闸门(防死循环)**:`main.py` 的 `_draw_run_check`(line ~4887,v5.0 引入)是"一条用户消息只出一次图"的硬保证。本轮已成功出图 / 已失败达上限就关门,模型无论再传什么都出不了图,从源头杜绝同一条消息反复刷图。

因此用户此前遇到的死循环,**基础防线在 v5.0.x 已在**;大概率是运行在 < v5.0 的旧版。升 v5.0.10 后应已不再发生。本设计的重点是补齐"剧情模式"这个会放大连续调图频率的场景。

> 真正缺的、需新增的只有两块:
> - **① 剧情模式白名单 + 进入/退出触发词**(全新功能)
> - **② 工具描述里的"收尾/停止"软规则**(目前工具描述只有"一条请求只调一次",未明写"收到收尾指令必须停、不得传空参重试")

## 5. 实现方案(v5.0.12)

### 5.1 配置(`_conf_schema.json` 新增 `story_mode` 块)

```json
"story_mode": {
  "enabled": false,
  "user_ids": "",
  "trigger_keywords": "进入剧情模式,开启剧情模式,剧情推演模式",
  "exit_keywords": "退出剧情模式,结束剧情模式,停,退出剧情"
}
```

- `enabled`:功能总开关。
- `user_ids`:允许进入剧情模式的用户 QQ,每行一个或逗号分隔。**留空 = 不限制用户(仅由 `enabled` 控制);非空 = 仅名单内可进**。与现有 `allow_draw_users`(发图白名单)相互独立。
- `trigger_keywords`:进入剧情模式的触发词(可配置)。
- `exit_keywords`:退出剧情模式的触发词(可配置)。
- hint 注明:这是隐藏功能,普通用户不应暴露;与发图白名单独立。

### 5.2 代码逻辑(`main.py`)

- `__init__` 新增 `self._story_sessions: set[str] = set()`(记录当前处于剧情模式的 session)。
- 新增轻量 `@filter.on_message()` 钩子 `_on_story_mode(event)`:
  - 若 `story_mode.enabled` 为 false → 直接 `return`(不拦截任何消息,零开销)。
  - 归一化文本(去首尾标点/空白)后,先比 `exit_keywords`、再比 `trigger_keywords`:
    - **命中退出词** 且 本 session 已在剧情模式 → 移除标记,回「已退出剧情模式。」,`event.stop_event()`。
    - **命中进入词** → 校验 `user_ids`(`_parse_id_list` 解析,空名单=放行,非空=必须命中);不在白名单回「你暂无剧情模式权限～」+ `stop_event()`;命中则把 session 加入 `_story_sessions`,回「已进入剧情推演模式:我会按步骤推进场景并配图,说「停」即可结束。」+ `stop_event()`。
  - 都不命中 → `return`(放行给正常对话流程)。
  - **匹配精度**:用"整句等于 / 以关键词开头"判定,避免"今天讲个剧情模式的故事"误触发;「停」只认整句,避免日常聊天误退。
- **绘图逻辑不改**:剧情模式下 LLM 自己调 `comfyui_draw`,现有的单轮闸门 + 空参报错天然兜底不循环。

### 5.3 工具描述增强(`comfyui_draw`,约 line 5905)

在现有「★一条用户请求只调一次」段之后追加两段(对所有模式生效,防死循环 + 剧情引导):

- **停止信号**:当系统或用户返回以下任一类指令时,**必须立即停止调用本工具、不得重试**:「本轮已调用,请勿再调用」「收尾」「结束本轮」「禁止继续」「停止/停」。重试会被单轮闸门直接拦回,且传空参数 `{}` 会被拒绝、越调越错。
- **剧情推演模式**:若当前处于剧情推演模式(用户说「进入剧情模式」开启,说「停」结束),请按剧情步骤推进——每条消息规划一个场景、用**完整 prompt** 调本工具配图,首尾必发图;不要在一条消息里反复调用,也绝不传空参数。

### 5.4 防死循环的保证层级

| 层级 | 机制 | 状态 |
|------|------|------|
| 硬 · 空参 | prompt 为空直接报错,不兜底 | 已实现(v5.0.x) |
| 硬 · 单轮 | `_draw_run_check` 本轮闸门 | 已实现(v5.0) |
| 软 · 停止信号 | 工具描述写明"收到收尾指令必须停" | 本版新增 |
| 软/权限 · 白名单 | `story_mode` 开关 + user_ids | 本版新增 |

## 6. Bot system prompt 建议(剧情推演规则)

AStrBot 4.27.4 的 `Context` 仅有插件主动发起 LLM 调用时的 `system_prompt` 参数,**没有"插件给主对话自动注入 system prompt"的注册式钩子**。因此"插件内整一个"只能落在工具描述(每次工具调用可见,对所有模式生效,作为开箱即用兜底);更细、更个性化的剧情推演风格,需由**用户写在 Bot 的 system prompt** 里(硬引导)。

插件工具描述已提供通用停止信号 + 剧情模式轻引导;建议在 Bot system prompt 追加(示例):

```
【剧情推演模式】
当用户说"进入剧情模式"后,进入剧情推演:你自动规划剧情步骤、推进场景,每条消息配文并调用 comfyui_draw 出图(首尾场景必发图,中间可每几步发一张)。
- 每次调用 comfyui_draw 必须传入完整画面描述(prompt),严禁传空参数。
- 收到系统返回"本轮已调用,请勿再调用""收尾""结束""停止"等指令时,立即停止调用画图工具,不要重试,用一句话自然收尾。
- 推演完一个章节或用户说"停"时,结束本轮剧情推演。
```

## 7. 流程图

```mermaid
flowchart TD
    A[用户消息] --> B{story_mode.enabled?}
    B -- 否 --> Z[正常流程]
    B -- 是 --> C{命中 进入/退出 关键词?}
    C -- 退出词 且 本会话在剧情模式 --> D[清标记<br/>回"已退出剧情模式。"<br/>stop_event]
    C -- 进入词 --> E{user_id 在 user_ids?}
    E -- 空名单/命中 --> G[标 session 为剧情模式<br/>回"已进入剧情推演模式…"<br/>stop_event]
    E -- 非空且未命中 --> F[回"你暂无剧情模式权限～"<br/>stop_event]
    C -- 否 --> H{本 session 已标记剧情模式?}
    H -- 是 --> I[正常流程<br/>LLM 按 Bot system prompt 推演<br/>+ 工具描述内置规则]
    H -- 否 --> Z
    I --> J{comfyui_draw 调用}
    J --> K["单轮闸门拦回(本轮已出图)<br/>空参 {} 报错<br/>停止信号 → 停调"]
```

## 9. 待确认 / 未决项

- `user_ids` 空值语义:采用"空 = 不限制(仅 enabled 控制)"还是"空 = 无人可进(严格白名单)"?文档暂按宽松(空=不限制)描述,实现时以用户最终确认为准。
- 触发词默认值是否覆盖常见的方言说法(如"开始剧情""剧情开始")——可后续按用户反馈扩充。
- 剧情模式的 LLM 推演质量依赖用户在 Bot system prompt 的配置;插件只提供开关、白名单与工具描述内的通用兜底规则。
