# TODO：主动发图 + 日程/亲密度联动

## 需求

机器人根据「日程表 + 人格 + 亲密度」，按概率**主动发消息并发图**（AI 伴侣式主动互动）：

- 每日/按日程表触发，但不是纯随机，而是**按概率**。
- 概率不是一成不变：根据**亲密度**（亲密越高越容易主动发图）加成。
- 发到**指定用户和指定群**。
- 图片**根据当前日程自动生成**（按日程的 prompt 模板生图后推送）。

## 关键决策（已确认）

- 归属：**只在本插件（astrbot-comfyui-anima）实现**，不改 / 不依赖他人伴侣插件的代码。
- 亲密度来源：**提供配置选项**——
  - 用本插件独立数据；
  - 或联动伴侣插件数据（读伴侣 `companions.json`）。

## 技术可行性（已调研）

- **主动发消息**：`Context.get_platform_inst(platform_id)` + `platform.send_by_session(MessageSession, MessageChain)`，可对指定会话/群主动推送（不依赖用户触发）。
- **生图**：复用现有 `comfyui_draw` / `_do_draw`，按日程 prompt 自动生成。
- **发图**：生图后把本地图片文件用 `Image.fromFileSystem` 拼进 `MessageChain`，再 `send_by_session` 推送。
- **伴侣亲密度字段**：伴侣存储里为 `relationship_score`（关系分，-1200~1200）、`affinity_band`（亲密阶段）、`relation_label`；数据在 `companions.json`（或 SQLite，视伴侣配置）。

## 实现难点 / 注意

- 读伴侣数据需**容错**：文件不存在 / 格式变动 → 降级到独立模式，不影响主流程。
- 伴侣插件**无对外的"查询亲密度"LLM 工具**，需直接读其数据文件，耦合其数据结构（伴侣是他人插件，格式可能变）。
- 主动调度需要**定时任务**（插件当前无定时机制），需新增后台循环 / 任务。
- 目标对象（指定群 / 用户 ID 列表）需持久化到 `_conf_schema`。

## 建议推进顺序

1. 先做**独立 MVP**：独立日程 + 基础概率 + 主动发图 + 指定群/用户（先跑通全流程）。
2. 第二步再加**伴侣亲密度联动**：读伴侣数据结构 + 概率加成 + 容错降级。
