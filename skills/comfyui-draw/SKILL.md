# ComfyUI 绘图技能（astrbot_plugin_comfyui_anima）

你拥有 ComfyUI 绘图能力，**唯一的出图方式是调用插件提供的 LLM 工具**。口头说"我会画""马上"不等于画了图。

## 你能做什么

通过调用插件提供的 LLM 工具出图：

- `comfyui_draw`：文生图 / 附带参考图时自动图生图。核心参数 `prompt`（必填）。
- `comfyui_img2img`：基于一张参考图做变换 / 重绘。`prompt` 传"变换意图"。
- `comfyui_loras`：查询当前已配置的 LoRA 库（名称、别名、底模、描述、触发词）。需要用户提到"用某个 LoRA / 某风格画"但你不确定可用列表时调用。
- `comfyui_workflows`：查询当前已配置的工作流列表（名称、是否支持图生图、是否 Anima）。
- `comfyui_gallery`：发**以前画过/收藏**的旧图（不属于"画新图"，不要用它替代出图）。

> 工具调用顺序：**comfyui_draw 永远是真出图的最终一步**。comfyui_loras / comfyui_workflows 只在"需要确认可用项"时作为前置查询，不是必做的前置流程——拿不准就直接不传 workflow/loras，让插件用默认，照样出图。

## 铁律 0：只要用户要【新】图，就必须真调 comfyui_draw，禁止只说不动

这是本技能最重要的一条。**用户说"画/生成/来张图/给我弄个图/换一张/再来一张/怎么还不出图"等任何要图意图时，必须调用 comfyui_draw（或 img2img）并真正等待出图结果。** 以下行为都是错误的：

- ❌ 只回复"好呀~这就给你画""马上动手✨""在跑图了，再等几秒"而不调用工具——这等于没画。
- ❌ 第一次调用出图失败/超时后，只回"我再试试"而不重新调用。
- ❌ 因为对话记忆里"画过了/之前说过要画"就不再调用。
- 用户催"图呢/卡住啦/怎么没看到图"时，**更要立即调用工具**（而不是解释）。

只要用户想要的是**新图**，无论多隐晦、无论对话聊了多久，都要真调工具。

## 数量规则：默认只画一张

- **默认只生成 1 张图**。用户没说数量，就只调用一次 comfyui_draw、只出 1 张。画完就自然收尾，不要自己补画第二张"换个姿势试试"。
- 只有用户**明确**说"两张/三张/多画几张/每张各来一版/所有姿势都来一遍"时，才按需求张数调用。
- 对话记忆里以前说过的"多发几张"**只对当时那次有效**，不代表这次也要多发。

## 图生图判定：只认"本次消息里的参考图"

- 当且仅当**用户当前消息里真的附了图片**（或明确说"把这张图/参考这张图/这张照片变成XX"）时，才走图生图（把参考图交给插件，或传 image 参数）。
- **历史消息里的图、群聊里别人发的图、之前画过的图，都不算参考图。** 用户只是说"换个场景动作再来一张"这种延续旧图的请求，走**文生图**（重新 comfyui_draw 生成新图），不要试图去历史里找图当参考。
- 普通文字请求一律文生图。不要因为群里/上下文里出现过图就把请求当作图生图。

## LoRA 怎么用（别再让用户给"确切名字"）

- 用户说"用 XX 的 lora""用那个鲸鱼娘 lora"这类话时：
  1. 先调 `comfyui_loras` 查询可用列表（可按底模过滤、按名称/别名模糊搜）。
  2. 从结果里按名称/别名匹配出确切名称，填进 `loras` 参数（如 `["ds_whale"]`）。
  3. 查不到/匹配不上就如实说"没有找到对应 LoRA"，不要编造名字。
- 用户给了名字但不确定是否准确，也可以先查 comfyui_loras 确认后填。
- 用户没提 LoRA → `loras` 参数不传，插件用配置默认。

## 工作流怎么填（同上原则）

- **默认不传 `workflow` / `img2img_workflow`**（插件用默认工作流）。
- 只有用户明确要特定画风（真人/写实/动漫/二次元/某名字）时，先调 `comfyui_workflows` 查真实列表，按名称语义匹配后再填。
- 禁止凭记忆猜工作流名；拿不准就宁可留空用默认，也不要瞎填。
- 图生图时若列表里有名字含「图生图」的工作流，优先选它。

## 提示词语言

| 工作流类型 | 判断标志 | 提示词语言 |
| --- | --- | --- |
| 真人 / 写实 | 非 Anima | **首选中文**；用户明确要英文才用英文 |
| 动漫 / 二次元 | Anima | **必须英文标签**（如 `1girl, solo, white dress, beach, backlight, masterpiece`），禁止中文 |

- 不确定类型时不传 workflow 用默认，并按默认工作流的类型写（通常真人→中文）。
- 负向提示词同样遵循语言规则。

## 完整出图流程

1. **判意图**：新图 → 本技能；旧图/收藏图 → comfyui_gallery；用户明确"不要图/取消" → 不画，文字回应。
2. **判数量**：默认 1 张；用户明确说几张才多画。
3. **判图生图**：本次消息带参考图才走图生图；否则文生图。
4. **需要指定则查询**：用户提 LoRA → comfyui_loras；提画风/工作流 → comfyui_workflows。没提就跳过。
5. **拼 prompt**：按语言规范写，可加姿势/光影/细节变化避免雷同。
6. **调用出图**：comfyui_draw（文生图）或 comfyui_img2img（本次消息有参考图）。prompt 必填。
7. **收尾**：把图交给用户，一句话结束。不要再补画、不追问"还要不要别的"。

## 群聊 / 被动场景

- 在群聊里被 @ 要图、或用户发了参考图，同样按上述流程立即调用工具，不要因为"群聊人多/怕打扰"就不画。
- 用户明确说"别发了/不用了"才停止。

## 示例

- "画只猫" → comfyui_draw，真人默认中文 `prompt="一只可爱的橘猫，坐在窗台上，午后的阳光"`，1 张。
- "用鲸鱼娘的lora画张海洋主题" → 先 comfyui_loras 找到鲸鱼娘 LoRA 的确切名，再 comfyui_draw `loras=["鲸鱼娘名"]`。
- "把这照片转成动漫风格"（本次消息附图）→ comfyui_img2img，参考图交给插件，prompt 英文标签。
- "换个场景和动作，再来一张"（没附图）→ comfyui_draw 重新生成新图，不要图生图。
- "画三张不同姿势的" → 明确三张，按 3 次调用（或按工具支持传数量）。
- "图呢/卡住了" → 立即再调 comfyui_draw，别解释。

## 不要做什么

- ❌ 只口头承诺"我会画"而不调工具（铁律 0）。
- ❌ 默认多画几张；用户没说数量就只出 1 张。
- ❌ 把历史/群聊里的图当图生图参考图。
- ❌ 让用户"给确切 lora 名字"——有 comfyui_loras 就自己查。
- ❌ 凭记忆填工作流名。
- ❌ 动漫工作流输出中文 prompt。
- ❌ 给 wf/lora/宽高/seed/denoise 传用户没要求的参数——能不传就不传，插件有默认。
